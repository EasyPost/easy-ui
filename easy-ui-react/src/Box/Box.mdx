# Box

A `<Box />` is a general-purpose container that exposes Easy UI's design tokens as props. It exists to absorb the styling that would otherwise be written as a one-off CSS module or an inline `style` object.

<Canvas of={BoxStories.Default} />

## Constrained and free properties

`<Box />` follows a single rule: **constrain what has a token scale, leave free what does not.**

Properties backed by a token scale are typed to that scale, so an invalid value is a type error:

| Property                             | Scale                    |
| ------------------------------------ | ------------------------ |
| `padding*`, `margin*`, `gap`         | space                    |
| `background`, `color`, `borderColor` | theme color              |
| `borderRadius`                       | border radius, or `full` |
| `borderWidth`, `border*Width`        | border width             |
| `boxShadow`                          | shadow level             |
| `zIndex`                             | z-index                  |
| `opacity`                            | opacity                  |

Easy UI has no size token scale, so sizing and positioning accept free CSS values. Numbers are treated as `px`; strings pass through untouched, which means percentages, viewport units, `calc()`, `fit-content`, and `auto` all work.

```tsx
<Box width="100%" maxWidth={700} height="calc(100svh - 96px)" />
```

## Space

`padding` and `margin` accept a space token, with per-axis and per-side variants. A more specific property wins over a less specific one, so `paddingTop` beats `paddingY`, which beats `padding`.

<Canvas of={BoxStories.Padding} />

<Controls of={BoxStories.Padding} include={["padding"]} />

`margin` additionally accepts `auto` and negated space tokens, for centering a box and for pulling one against its own flow.

```tsx
<Box marginX="auto" marginTop="-2" />
```

## Size

A `<Box />` can be sized directly. A constrained, centered container is the most common case.

## Border

Setting `borderColor` or a border width implies a solid border, so there is no `borderStyle` prop. A `borderColor` on its own implies a border width of `1`.

<Canvas of={BoxStories.Border} />

<Controls of={BoxStories.Border} include={["borderColor", "borderRadius"]} />

Widths can be set per side, which is how a `<Box />` becomes a divider or a ruled row.

```tsx
<Box borderBottomWidth="1" borderColor="neutral.200" />
```

Because a `borderColor` on its own implies a border, a conditional rule has to drop the color along with the width. Leaving the color behind draws a box on all four sides instead of no rule at all.

```tsx
<Box
  borderBottomWidth={isRuled ? "1" : undefined}
  borderColor={isRuled ? "neutral.200" : undefined}
/>
```

## Flexing within a parent

A `<Box />` can control how it behaves inside a flex parent such as a `<HorizontalStack />` or `<VerticalStack />`. This is what `flex`, `flexGrow`, `flexShrink`, `flexBasis`, `alignSelf`, and `order` are for.

<Canvas of={BoxStories.Flex} />

## Laying out children

A `<Box />` can lay out its own children with `display`, `flexDirection`, `flexWrap`, `justifyContent`, `alignItems`, and `gap`.

Prefer `<HorizontalStack />`, `<VerticalStack />`, and `<HorizontalGrid />` for this; they are named for their intent and are easier to read. Reach for `display` on a `<Box />` when those do not fit.

## Elements and resets

`as` renders a `<Box />` as a different element. `button`, `a`, `ul`, `ol`, `fieldset`, and `legend` receive an automatic unstyled reset, so their default browser styling does not need to be stripped by hand.

A `<Box />` keeps its element's own `display` until one is set: a `div` stays block, a `span` stays inline, an `img` stays inline. The same is true of `overflow` and `text-align`, so a `<Box as="button" />` stays center-aligned and a `<Box as="img" />` still clips an `objectFit="cover"` image to its box.

<Canvas of={BoxStories.ElementReset} />

## Responsive properties

Most properties accept an object keyed by breakpoint. A value applies from its breakpoint upward until another value overrides it.

<Canvas of={BoxStories.Responsive} />

```tsx
<Box padding={{ xs: "2", md: "6" }} maxWidth={{ xs: "100%", lg: 480 }} />
```

`color`, `objectFit`, `whiteSpace`, `cursor`, `pointerEvents`, `zIndex`, `boxShadow`, `borderColor`, border widths, and `opacity` are deliberately not responsive, to keep the stylesheet small.

## Recipes

The sections above show one property at a time. Each recipe below replaces a pure-layout CSS module that exists in the EasyPost web app today, and says how many times that shape is currently copy-pasted. They are meant to be copied — and, where a module is entirely layout, to delete it.

Three shapes are deliberately missing. A plain card surface, a title-and-action section header, and a selectable card are already owned by `Card`, `SectionCard`, and `CheckableCard` — the app reaches for `Card` in around 198 files. A search row is missing too: the app builds it with `HorizontalGrid columns={["1fr", "auto"]}`, not with a flexing wrapper. A Box recipe for any of them would teach people to hand-roll a component we ship.

### Page container

A centered, width-capped content column. `margin: 0 auto` beside a `max-width` appears in 10 rules across 7 modules — 1320px for the sub-account layout, 900/1080/800px three times over in one onboarding module, 988px for the Nexus FAQ.

<Canvas of={BoxStories.PageContainer} />

### Control width cap

Capping one control rather than centering a page. Around 25 modules do this; the FlexRate adjustment editor has nine in a single file, and one module's entire contents is `.searchContainer { width: 100% }`.

<Canvas of={BoxStories.ControlWidthCap} />

### Centered page

A full-height centered shell around a single card, from the OAuth authorize lander. It is the newest CSS module in the app and every one of its rules is pure layout, so a `<Box />` deletes the file outright.

<Canvas of={BoxStories.CenteredPage} />

### Divider

One hairline rule, which the app draws eleven times across eleven modules in five mutually incompatible ways: `border-top`, `height: 1px` with a `background`, `min-height: 1px` with a `background-color`, `height: 0` with a `border-bottom`, and a whole `<Separator />` component whose body is a single styled `<div />`.

<Canvas of={BoxStories.Divider} />

### Panel header

A padded header band with a rule under it — byte-identical across three sub-account modules. The title-and-action row inside is a `HorizontalStack`; only the band needs a Box.

<Canvas of={BoxStories.PanelHeader} />

### Scroll panel

A fixed-height panel whose middle section scrolls. `flex="1"` with `minHeight={0}` and `overflowY="auto"` is the trio that is easy to get wrong: without `minHeight={0}` the flex item refuses to shrink, so the panel grows instead of scrolling.

<Canvas of={BoxStories.ScrollPanel} />

### Centered overlay

A spinner centered over the content it stands in for. Two analytics quick-link modules hold this shape byte-for-byte, `@use` line included. The real code crossfades the two layers with an inline `opacity`; this covers the lower one with an opaque `background` instead, which is the same layout without the fade.

<Canvas of={BoxStories.CenteredOverlay} />

### Sticky banner

A banner pinned to the top of a scrolling dialog, byte-identical across three modal modules. `zIndex` is constrained to the token scale, which is what keeps `z-index: 9999` out of application code.

<Canvas of={BoxStories.StickyBanner} />

### Carrier logo

A fixed-size box holding a contained image — the most copy-pasted layout shape in the app, at 20 `object-fit: contain` declarations across 13 modules in six different sizes.

<Canvas of={BoxStories.CarrierLogo} />

### Card button

A whole card that is also a button. Five modules hand-write `all: unset` to reach this. `as="button"` applies the same reset without discarding the focus ring, which is what `all: unset` costs.

<Canvas of={BoxStories.CardButton} />

### Icon rail field

A labelled field with an icon rail beside it. The same 35 lines are copy-pasted into three unrelated features, and the JSX is triplicated with them. The rail itself is a `::before`, which no style prop can express — so most of that module goes away, not all of it.

<Canvas of={BoxStories.IconRailField} />

### What these recipes could not absorb

Three details in the real modules survive a Box, and they are all token or API gaps rather than reasons to keep a stylesheet:

- The loading overlay crossfades with an inline `opacity: 0 | 1`. `opacity` is token-only and that scale has exactly one alias, `underlay`.
- The sticky banner rounds only its bottom two corners. `borderRadius` applies to all four.
- The icon rail is drawn with a `::before`, which is out of scope for a style prop by design.

## No className, no style

`<Box />` accepts neither `className` nor `style`. It is the escape hatch, so it cannot itself have one — an escape hatch on the escape hatch would put arbitrary CSS back into application code and take styling out of the token system.

If a `<Box />` cannot express something you need, that is a gap in `<Box />`. **File it.** The fix belongs here, where every consumer gets it, rather than in one application's stylesheet.
